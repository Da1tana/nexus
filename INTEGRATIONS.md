# INTEGRATIONS — фактические возможности источников

Документ описывает, что NEXUS **реально** умеет с каждым источником в текущей версии,
и почему не умеет остального. Таблица синхронизирована с `core/engine/.../SourceCatalog.kt`.

Состояние исследования: ноябрь 2026. Ограничения сторонних сервисов меняются — перед реализацией
уровня C каждую позицию нужно перепроверить по официальной документации.

## Уровни интеграции

| Уровень | Механизм | Что даёт | Чего не даёт |
|---|---|---|---|
| **A — уведомления** | `NotificationListenerService` | Текст, отправитель, время, беседа — для сообщений, пришедших уведомлением после установки NEXUS | Историю до установки; сообщения из заглушенных чатов; полный текст, если приложение его скрыло |
| **B — быстрый ответ** | `RemoteInput` + `PendingIntent` действия «Ответить» | Ответ из NEXUS, пока уведомление беседы активно | Ответ после того, как уведомление смахнули/прочитали; подтверждение доставки (только косвенно) |
| **C — официальный API** | API сервиса + OAuth/токены в Android Keystore | История, диалоги, отправка без уведомлений, статусы | Есть не у всех сервисов и почти никогда — для личных аккаунтов мессенджеров |

Кроме таблицы, в каталоге (`SourceCatalog`) — MAX, ТамТам, Signal, Discord, Instagram, Одноклассники, Kate Mobile,
Яндекс Мессенджер, MeeTime, Element, Threema, Skype, LINE, WeChat, Snapchat, X, Slack, Teams, Google Chat, Mattermost,

даёт кнопку «Ответить»); официальных API для личной переписки у них в v0.2 не используется.

Приложения вне каталога включаются автоматически, если их уведомление похоже на сообщение (категория msg/email/social,
MessagingStyle или кнопка ответа). Прочие (магазины, банки, системные) видны на экране «Приложения» и включаются вручную.

## Как работает быстрый ответ (уровень B)

1. Сервис получает уведомление и ищет действие с `RemoteInput`, допускающим свободный ввод
   (сначала обычные действия, затем `WearableExtender` — его используют часть мессенджеров).
2. Живой `Notification.Action` хранится только в памяти (`ActiveNotificationRegistry`) — в базу его сохранить нельзя.
3. При отправке NEXUS заполняет `RemoteInput` текстом и вызывает `PendingIntent` — так же, как шторка уведомлений.
4. Статус: `SEND_PENDING` → после вызова `UNKNOWN` («передано приложению, без подтверждения»).
5. Если мессенджер обновляет уведомление и показывает наш ответ как исходящее сообщение MessagingStyle
   (так делают Telegram, WhatsApp, Google Messages), NEXUS сопоставляет текст и ставит `SENT`.
6. `PendingIntent.CanceledException` → `FAILED` с причиной.
7. Если уведомления нет — ответ из NEXUS недоступен, UI предлагает открыть исходное приложение.

NEXUS **не использует** Accessibility Service для управления чужими интерфейсами и не читает базы других приложений.

## Известные ограничения уровня A

- Сообщения из заглушенных (muted) чатов не создают уведомлений — в NEXUS не попадут.
- Если в мессенджере включено «скрывать текст в уведомлениях», сохраняется только факт сообщения (помечается «Текст скрыт»).
- InboxStyle-уведомления без меток времени: две одинаковые строки в одной беседе склеиваются в одно сообщение.
- Вложения: сохраняется только тип (изображение/видео/аудио), не содержимое — URI из уведомлений временные.
- В групповых чатах отправители с одинаковым именем в одном источнике считаются одним аккаунтом.
- Беседа определяется по `shortcutId` (если есть) или заголовку; переименование чата без `shortcutId` создаст новую беседу.
